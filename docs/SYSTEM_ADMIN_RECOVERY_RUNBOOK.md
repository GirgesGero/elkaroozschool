# استرداد وصول مسؤول النظام

## النطاق

إجراء طارئ لاستعادة الوصول عندما يتعذر على المسؤول الحالي استخدام حسابه، مع بقاء سجل مسؤول نظام نشط واحد بالضبط. لا ينشئ الإجراء مسؤولًا ثانيًا ولا يغيّر بيانات اعتماد الحسابات.

## ضوابط واجبة قبل التشغيل

1. افتح حادثة موثقة لدى مالك مشروع Supabase، وتحقق من هوية طالب الاسترداد عبر قناة مستقلة موثوقة، لا عبر البريد الوارد في الطلب نفسه.
2. اشترط موافقة شخصين مخولين، وسجّل مرجع الحادثة ومرجع الموافقة في سجل التغيير. لا تضع كلمات مرور أو JWT أو مفاتيح في مراجع السجل.
3. اختر حسابًا نشطًا مؤهلًا (`supervisor` أو `servant` أو `secretariat`) وتحقق من صاحبه خارج قاعدة البيانات.
4. خذ نسخة احتياطية محمية قبل الإجراء، وافحص أن هناك مسؤول نظام نشطًا واحدًا فقط.
5. نفّذ الدالة من جلسة SQL موثوقة مسجلة الدخول بدور قاعدة البيانات `postgres` فقط. الدالة غير ممنوحة لـ`authenticated` أو `service_role` أو `anon`، ويفشل الاستدعاء إذا لم يكن `session_user = 'postgres'`.

## النقل الطارئ

استدعِ `public.system_admin_break_glass_recovery(uuid, text, text, text)` ضمن معاملة واحدة من SQL Editor/اتصال المالك، مع تمرير معرّف الملف الشخصي المستهدف، والعبارة الحرفية `RECOVER SYSTEM ADMIN`، ومرجع المشغّل، ومرجع الموافقة. لا تستدعِها من واجهة التطبيق أو PostgREST. إذا رفضت الدالة لأن المسؤول الحالي مفقود أو لأن العدد ليس واحدًا بالضبط، أوقف المحاولة؛ لا تنفذ إدراجًا أو تعديلًا يدويًا لتجاوز القيد، وصعّد الحالة إلى إجراء استرداد مُراجع مع مزود قاعدة البيانات.

بعد نجاح الاستدعاء، اقرأ `profiles` للتحقق من أن الهدف وحده يحمل الدور النشط `admin`، وأن الحساب السابق لم يعد `admin`، ثم راجع صف `audit_logs` ذي الإجراء `SYSTEM_ADMIN_BREAK_GLASS_RECOVERY`. أبلغ المسؤول الجديد بإعادة تسجيل الدخول وإبطال الجلسات القديمة عبر إجراء مزود الهوية المعتمد. لا تعتبر وجود نتيجة من الدالة وحده تحققًا نهائيًا.

## ملاحظات أمنية وتشغيلية

- مرجع المشغّل/الموافقة نص توثيقي؛ التحقق من الهوية وموافقة الشخصين مسؤولية عملية الحادثة خارج قاعدة البيانات.
- لا توجد آلية تلقائية لإعادة إنشاء المسؤول عند غيابه، عمدًا. استعادة حالة بلا مسؤول تتطلب مراجعة مزود موثقة ومهاجرة تحت إشراف مالك قاعدة البيانات.
- لا تشغّل migration أو إجراء الاسترداد على الإنتاج قبل مراجعة SQL كاملًا وتجربته على قاعدة PostgreSQL معزولة وأخذ موافقة تشغيلية منفصلة.
