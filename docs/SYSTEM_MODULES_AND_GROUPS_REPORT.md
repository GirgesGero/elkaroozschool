### 2. كيف تم تنظيم الفرق والعزل (Groups Architecture)
- **الفرق الدراسية الثلاث:**
  1. **الفرقة الأولى (Group 1)**
  2. **الفرقة الثانية (Group 2)**
  3. **الفرقة الثالثة (Group 3)**
- **مستوى العزل في النظام:**
  - **على مستوى الواجهة (`/trainees`, `/attendance`, `/gallery`, `/mp3`):** الخادم والسكرتارية والمتدرب يرون حصرياً بيانات فرقتهم.
  - **على مستوى قاعدة البيانات (Row Level Security):** جداول الحضور، الطلاب، والوسائط مفصولة برمجياً بـ `group_id` وسياسات Postgres RLS تمنع وصول أي مستخدم لبيانات فرقة أخرى منعاً باتاً.
  - **المسؤول والسوبر يوزر:** يمتلكان فلتر لاختيار وعرض أي فرقة دراسية (`Group 1`, `Group 2`, `Group 3`).

### 3. كيف تعمل إدارة الإشعارات (Notification Engine)
- **الفئات الثلاث الحصرية المعتمدة في SRS:**
  1. **إشعارات الافتقاد والغياب (Pastoral Absence):**
     - تنطلق آلياً وفورياً عند رصد غياب الطالب يوم الجمعة، وتوجه للمتدرب وخدام وسكرتارية فرقته فقط.
     - القالب الافتراضي يدعم `{{student_name}}` ويتم التحكم فيه من `/admin/notifications`.
  2. **إشعارات أعياد الميلاد (Birthdays):**
     - تنطلق بناءً على تاريخ الميلاد المسجل، وتوجه تهنئة شخصية للطالب وتنبيه لمجتمع المدرسة.
  3. **الآيات اليومية (Daily Verses):**
     - تُدار من بنك الآيات بجدولة (يوم إرسال ويوم راحة) عبر نظام التدوير التسلسلي أو العشوائي.
- **مركز الإشعارات في الواجهة:**
  - أيقونة الجرس التفاعلي `NotificationCenter` في الشريط العلوي للصفحة الرئيسية، تعرض عدد الإشعارات غير المقروءة، وتحديث حي Live عبر Supabase Realtime مع دعم الـ Web Push والإشعارات المحلية.
